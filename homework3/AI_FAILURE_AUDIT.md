
# Homework 3: AI Failure Mode Audit

## Overview

This report documents three issues identified while developing the Resilient Event Hub with AI assistance. The issues were reviewed through browser testing, code inspection, and Git history. Each case explains the problem, how it was identified, and the solution applied or proposed.

## Defect 1: ISO 8601 Timestamp Validation Failure

### Defect Description
The initial countdown implementation used a regular expression that only accepted UTC timestamps without milliseconds.

When a timestamp generated by JavaScript's `toISOString()` was used, the countdown displayed "Invalid event deadline" instead of calculating the remaining time.

### Diagnostic Method
The issue was discovered while testing the countdown with a deadline approximately 15 seconds in the future.

The browser displayed the validation error because `toISOString()` included milliseconds, while the original regular expression did not allow them.

The validation condition in `app.js` was inspected to identify the mismatch.

### Refactored Solution
The regular expression was updated to accept an optional millisecond component.

The countdown was tested again with a UTC timestamp containing milliseconds. It successfully reached zero and displayed "The event has started!".

### Verification
- Countdown accepts UTC timestamps with milliseconds.
- Countdown reaches zero correctly.
- No JavaScript console errors were observed.

## Defect 2: Missing Double-Submit Protection

### Defect Description
The initial AI-generated form state machine changed the button text to "Submitting..." but did not disable the button or reject additional submit events.

This allowed multiple submission handlers to potentially run while a previous registration was still processing.

### Diagnostic Method
The issue was identified by reviewing the form submission logic and comparing Git commits `7ac07a7` and `34b9431`.

The earlier version did not contain a guard for the SUBMITTING state or disable the submit button.

### Refactored Solution
The submit button was disabled while the form was processing.

A state check was added at the beginning of the submit event handler to ignore repeated submissions during SUBMITTING.

### Verification
- The Register button becomes disabled during submission.
- Additional submit events are ignored while processing.
- The button becomes available again after completion.
- The form continues to work without console errors.

## Defect 3: Invalid State Transition in an AI Suggestion

### Defect Description
During input validation improvements, an AI suggestion attempted to call `transitionTo(ERROR)` when a required form element was missing.

However, the state machine only allowed IDLE to transition to SUBMITTING. A direct transition from IDLE to ERROR was not supported.

The issue was identified during code review before the suggestion was applied.

### Diagnostic Method
The proposed error-handling code was compared against the allowed transitions defined in the `transitionTo()` function.

The review showed that the transition would return false when the current state was IDLE, preventing the intended error-state update.

### Refactored Solution
Instead of calling an unsupported state transition, the configuration error was displayed through the existing status element using `textContent`.

This avoided changing the state machine's transition rules.

### Verification
- The invalid transition was not added to the application.
- The implemented error message uses `textContent`.
- The normal registration flow continued to pass testing.

## Conclusion

These issues show why AI-generated code still needs manual review and testing. Browser tests helped identify the countdown problem, while Git history and code inspection helped detect issues in the form logic. By fixing or rejecting the problematic suggestions, the application became more reliable and easier to maintain.
